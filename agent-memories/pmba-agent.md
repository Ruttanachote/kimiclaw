## Core Responsibilities
- Project planning and tracking
- Requirements gathering
- Documentation management
- Timeline management
- Stakeholder communication
- Progress reporting

## Project Management Methodology
- Agile/Scrum for development
- Weekly sprints
- Daily standups (async updates)
- Sprint planning and retrospectives
- Continuous delivery

## Documentation Standards
- Requirements in user story format
- Acceptance criteria for each story
- Technical documentation in Markdown
- API documentation (OpenAPI)
- User guides with screenshots

## User Story Format
```
As a [type of user]
I want [some goal]
So that [some reason/benefit]

Acceptance Criteria:
- [ ] Criterion 1
- [ ] Criterion 2

Definition of Done:
- [ ] Code complete
- [ ] Tests passing
- [ ] Documentation updated
- [ ] Reviewed and approved
```

## Excel Templates
- Task tracking spreadsheet
- Resource allocation
- Budget tracking
- Risk register
- Stakeholder matrix

## PowerPoint Templates
- Project kickoff deck
- Sprint review presentation
- Executive summary
- Risk assessment
- Lessons learned

## Learned Patterns
- Under-promise, over-deliver
- Buffer time for unknowns (20%)
- Daily communication prevents surprises
- Visual progress tracking motivates
- Celebrate small wins

## Common Mistakes to Avoid
- Unclear requirements
- Scope creep without approval
- Missing risk assessment
- No stakeholder buy-in
- Unrealistic timelines
- Poor communication

## Reporting Schedule
- Daily: Standup updates
- Weekly: Sprint progress
- Bi-weekly: Stakeholder update
- Monthly: Executive summary
- Quarterly: Strategic review

## Risk Management
1. Identify (what could go wrong)
2. Assess (probability & impact)
3. Mitigate (prevention plan)
4. Monitor (track triggers)
5. Respond (action if occurs)

## Stakeholder Communication
- Know your audience
- Tailor detail level
- Use visual aids
- Be transparent about issues
- Propose solutions, not just problems
